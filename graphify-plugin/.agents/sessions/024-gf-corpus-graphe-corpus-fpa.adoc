== Réalisations

=== GF-CORPUS-1 — Audit schéma (1 pt) ✅

Audit du code (`GraphModel.kt`, `ScanWorkspaceTask.kt`) contre les 3 besoins
du corpus FPA :

|===
| Besoin corpus | Couverture schéma existant | Verdict
| Pages OCR (`scans/000.adoc`…) | nœuds `file` + edges `contains` | ✅ couvert
| Sections (titres `=`/`==`/`===` de livre.adoc) | aucun type `section` | ❌ manquant
| Liens TOC (cellules `| 000.adoc |` de toc.adoc) | regex ne capte ni cellules ni nom simple | ❌ manquant
|===

Verdict : extension de schéma nécessaire → GF-CORPUS-3 déclenché (conforme
décision D4 du cadrage).

=== GF-CORPUS-3 — Extension schéma TDD strict (1 pt) ✅

5 baby-steps RED→GREEN, un type = un test :

. *U1 nœuds `section`* — `headingRegex` `^(=+)\s+(.+?)\s*$` (exclut
  les délimiteurs de blocs `====`), extraction par fichier adoc, metadata
  `level`/`line`/`source`. 2 tests.
. *U2 edges `has_section`* — fichier → section. Bug trouvé en chemin :
  `file.toString()` donnait le chemin absolu → corrigé en
  `root.relativize(file)`. 1 test.
. *U3 edges `subsection`* — hiérarchie par pile (parent = dernier titre de
  niveau strictement inférieur, jamais cross-fichier, niveau 1 sans parent).
  Attente de test initiale (chaîne linéaire) corrigée — la sémantique
  AsciiDoc impose la pile. 1 test.
. *U4 `reference` TOC* — regex cellules de table
  `\|\s*([\w./-]+\.(?:adoc|ad))\s*(?:\||$)` + résolution par nom de fichier
  (`resolveTocReference` : direct d'abord, puis match sur `fileName`).
  Label `toc_entry`. 1 test.
. *U5 unicité IDs* — sections homonymes suffixées `~N`
  (`book.adoc#Intro~2`). 1 test.

+ Test d'intégration end-to-end `FpaCorpusKnowledgeGraph` (mini-corpus
miroir FPA : scans + livre + toc). Attente corrigée : les pages OCR ont
aussi leur titre `= Page NNN` (légitime).

Décision méthode : pas d'infra Cucumber dans ce borough (library pure
JUnit5, zéro dépendance cucumber au build). Le cadrage D5 demande le TDD
strict ; la couverture BDD est assurée par 7 tests unitaires + 1 test
d'intégration end-to-end. Cucumber serait une addition de dépendance hors
périmètre EPIC (économise l'encre).
