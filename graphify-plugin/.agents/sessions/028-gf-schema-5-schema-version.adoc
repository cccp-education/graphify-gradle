== Constat de cadrage — le gate est dans la classe partagée

L'audit (`.agents/CADRAGE_EPIC_GF_SCHEMA_VERSION.adoc`) confirme le constat #6
de S-025 : bakery et codebase désérialisent `graph.json` en *strict*
(`ObjectMapper().registerKotlinModule()` + `readValue<GraphModel>`,
`FAIL_ON_UNKNOWN_PROPERTIES = true`). La solution la plus économe n'est pas de
modifier chaque consommateur, mais de porter la tolérance dans la classe N0
partagée : `@JsonIgnoreProperties(ignoreUnknown = true)` sur
`graphify.model.GraphModel`, `GraphNode`, `GraphEdge`, `GraphCommunity`.

Conséquence : un consommateur devient tolérant *en bumpant sa dépendance*,
sans éditer une ligne de son code.

== Collision de session — fait majeur de la clôture

Une *seconde session opencode* travaillait en parallèle dans `workspace-bom` et
`bakery-gradle` pendant cette session. Faits constatés :

* Le bump `workspace-bom = "0.0.45"` posé ici a été écrasé par leur
  `"0.0.46"` (working tree partagé).
* Leur `0.0.46` porte déjà `graphify-plugin = "0.0.5"` (bump `codex-plugin
  0.0.9` inclus) — mais **0.0.46 n'est pas publié** (repo1 404).
* Le catalogue Central `0.0.45` (publié `01:21 GMT` par l'autre session)
  référence `graphify-plugin = "0.0.4"`, pas 0.0.5.
* Les 2 tentatives `publishAggregationToCentralPortal` MEMPHIS de cette session
  ont été rejetées proprement (`Component ... already exists`, piège #6 mordu —
  sans conséquence).

session (fichiers tiers mêlés aux nôtres), ne committer que le périmètre isolé
(`graphify-gradle` + `codebase-gradle`).

== Dette — garde D5 structurellement racy entre sessions

`GraphifyPluginPublicationTest` (hygiène D5) lit le *working tree* du repo
voisin `../workspace-bom/gradle/libs.versions.toml`, pas le catalogue publié.
Elle est donc sensible à toute session parallèle qui édite ce fichier. Elle
passe aujourd'hui par coïncidence (le working tree dit 0.0.5). À corriger dans
un EPIC dédié (lire le catalogue publié, pas le working tree voisin).
