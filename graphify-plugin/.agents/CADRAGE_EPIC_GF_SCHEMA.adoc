== Décisions architecturales

. *Non destructif d'abord.* Aucun type existant n'est renommé dans cet EPIC.
   Le vocabulaire émis reste *byte-identique* (constat #5 : renommer =
   régression silencieuse chez bakery/codebase, non détectée par `check`).

. *`graphify.schema` — domaine Gradle-free, registre unique des littéraux.*
   Nouveau domaine `graphify.schema` (objet pur, zéro dépendance Gradle) :
   `NodeType`/`EdgeType` (enums canoniques), `GraphSchema` (registre +
   résolution d'alias). `ScanWorkspaceTask` cesse d'écrire des chaînes
   littérales et passe par `GraphSchema` — *single source of truth*.

. *Mécanisme d'alias — entrée tolérante, sortie canonique.*
   `canonicalizeNodeType(raw)` / `canonicalizeEdgeType(raw)` :
   * un type canonique → inchangé (idempotent) ;
   * un alias connu → résolu vers le canonique (ex. `imports` → `import`,
     `module` → `project`, `dir` → `directory`) ;
   * un type *inconnu* → **préservé tel quel** (jamais perdu, jamais
     silencieusement remplacé). Règle d'or : le schéma tolère l'avenir.

. *Direction de canonicalisation = singulier (état actuel) — inversible en 1 ligne.*
   Puisque les consommateurs codent en dur le singulier, `import`/`reference`/
   `agent_reference` restent canoniques. Le jour où les consommateurs adoptent
   le pluriel UA (bump cross-borough), on inverse la table d'alias dans
   `GraphSchema` *sans toucher* `ScanWorkspaceTask` ni ses tests de forme.

. *Vocabulaire réservé (déclaré, non émis).* Les types UA non produits
   (`domain`, `flow`, `step`, `service`, `endpoint`, `config`, `concept` ;
   arêtes `depends_on`, `deploys`, `documents`, `similar_to`) sont *déclarés*
   dans le registre pour que les consommateurs puissent valider/filtrer sans
   deviner. Leur *détection* est un EPIC futur (elle changerait la sortie —
   ex. `build.gradle.kts` deviendrait `config` — donc interdite tant que
   bakery/codebase n'ont pas adopté).

. *`schemaVersion` — DIFFÉRÉ (décision explicite).* Ajouter un champ top-level
   à `GraphModel` casse les 3 consommateurs stricts (constat #6). Le
   versionnement de schéma est donc *hors* de cet EPIC : il exige d'abord un
   `@JsonIgnoreProperties(ignoreUnknown = true)` cross-borough + bump des
   dépendances. `schemaVersion` reste porté par `dashboard-data.json` (ALGER),
   qui est un contrat *neuf* sans consommateur legacy.

. *Rétrocompat garantie par garde de test.* Un `graph.json` legacy doit rester
   désérialisable par un `GraphModel` strict (sans champ ajouté). Garde
   fonctionnelle + BDD dédiées.

. *English only* — code, commentaires, Gherkin (règle transverse).

. *Méthode* : baby-step DDD/TDD/BDD strict RED → GREEN → REFACTOR, 3 niveaux
   (unit → functional → cucumber). Révision de la décision S-024 (« pas de
   Cucumber dans ce borough ») : l'EPIC touche un *contrat public*, l'infra
   Cucumber est désormais justifiée (cf. § Méthode).

== Gates et risques

* *Non-régression* : `./gradlew test` VERT (baseline 70 tests, 0 FAIL).
  Tout type émis doit rester identique → les 70 tests existants sont la garde.
* *Rétrocompat consommateurs* : aucun type renommé, aucun champ ajouté au JSON.
* *`module` fantôme* : le résoudre dans cet EPIC (alias `module` → `project`)
  documente l'ambiguïté sans changer la sortie.
* *README désynchronisé* (constat #7) : synchroniser les 10 READMEs (EN + 9
  traductions) dans une US de documentation, *pas* dans le code.
* *Dette cross-borough* : GF-SCHEMA-5 (schemaVersion) est un chantier
  multi-borough — il ne doit pas être absorbé subrepticement dans une session
  graphify.

== Méthode — Révision de la décision S-024

S-024 avait acté « pas d'infra Cucumber dans ce borough (library pure JUnit5,
tests unitaires + intégration suffisent) ». Cet EPIC *révise* cette décision :
GF-SCHEMA touche un *contrat public consommé par 5 boroughs*. Le niveau BDD
(Cucumber) est désormais justifié pour figer le comportement du schéma en
langage métier (canonicalisation, tolérance aux inconnus, rétrocompat).

L'infra Cucumber est *minimale* et consomme le convention plugin centralisé
`education.cccp.build.cucumber` v0.0.4 (ABIDJAN N0) — pattern document-gradle /
slider-gradle, zéro boilerplate local.
